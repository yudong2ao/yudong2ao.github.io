> **核心架构**：放弃篡改快捷方式与本地补丁注入，采用网络层透明代理方案，让 Figma 的汉化在任意启动路径下永久生效。

## 前言

UI 设计师与前端工程师对 Figma 再熟悉不过。然而官方桌面版长期缺乏官方中文支持，市面上主流的汉化方案往往存在以下硬伤：

1. **快捷方式劫持**：通过修改桌面快捷方式的目标参数注入加载项。一旦在软件内点击了“立即更新重启”，或者在文件管理器中双击 `.fig` 文件直接唤醒客户端，汉化就会立刻失效；
2. **客户端硬替换**：直接覆盖 Electron 打包文件，每次官方推送小版本更新，注入的文件就会被全部重写，必须重新走一遍繁琐的补丁流程；
3. **C 盘膨胀**：Figma 频繁的静默增量升级会在 `AppData` 目录下残留大量的历史版本垃圾文件夹（`app-xxx`），久而久之蚕食大量 C 盘空间。

为了彻底终结“更一次崩一次”的恶性循环，我尝试换个维度思考：**能不能不在本地文件上动刀，而是把战线拉到网络请求层？**

由此，**FigmaCn-Proxy** 诞生了。

---

## 核心架构：网络层降维打击

Figma 桌面版本质上是一个基于 Chromium 的客户端，它的多语言资源同样通过网络 API 请求下发。

本项目彻底抛弃了“劫持快捷方式参数”的传统做法，改用 **“透明代理 / 进程级代理”** 方案：

```text
┌──────────────────────────────┐
│  Figma.exe (桌面端任意方式唤起)│
└──────────────┬───────────────┘
               │ 1. 拦截目标进程流量 (ProxyBridge / Proxifier)
               ▼
┌──────────────────────────────┐
│ 本地代理网关 (127.0.0.1:8089) │
│ 基于 mitmdump + Python 拦截   │
└──────────────┬───────────────┘
               │ 2. 匹配语言包请求，重定向至第三方中文语言包
               ▼
┌──────────────────────────────┐
│      无缝呈现中文界面        │
└──────────────────────────────┘
```

无论你是通过开始菜单启动、在浏览器打开 Figma 协议链接、双击 `.fig` 本地文件，还是软件完成内建静默更新后自动重启——由于流量拦截发生在底层网络驱动层，Figma 的请求都会被无缝拦截并注水汉化资源。

---

## 贴心设计：零驻留启动与自动瘦身

为了保证使用体验的清爽，项目配备了专属启动器 `FigmaCn.vbs`：

1. **静默拉起**：在后台无黑框静默运行 `mitmdump`（监听在 `8089` 端口，并挂载专用重定向脚本 `figma_zh_cn.py`）；
2. **磁盘瘦身**：启动的同时自动巡检 Figma 安装路径，智能清理旧版本更新产生的遗留废弃目录（`app-xxx`），长期使用也能为 C 盘省出宝贵空间；
3. **零内存常驻**：执行清理与拉起后，VBScript 脚本自身立刻退出销毁，绝不占用系统常驻资源。

## 快速食用指南

项目提供预打包的**“开箱即用懒人包”**（内置免配置的 `mitmdump.exe`）：

### 第一步：初次信任根证书（仅需一次）

1. 运行 `mitmdump.exe` 生成本地证书后关闭；
2. 打开 `C:\Users\用户名\.mitmproxy\`，双击 `mitmproxy-ca-cert.p12`；
3. 导入时存储位置选 **“当前用户”**（无需管理员权限，更安全）；
4. 证书存储区域务必选择 **“受信任的根证书颁发机构”**，点击完成并确认信任。

### 第二步：配置进程分流

在你的进程代理工具（如 [ProxyBridge](https://github.com/yudong2ao/ProxyBridge_CLI_Plus) 或 Proxifier）中添加一条进程规则：

- **目标进程**：`Figma.exe`
- **动作 (Action)**：转发给 HTTP 代理 `127.0.0.1:8089`。

### 第三步：一键运行与开机自启

直接双击 `FigmaCn.vbs`，即可一键静默拉起后台服务并清理垃圾。建议为该脚本创建快捷方式放入 Windows 启动目录（`Win+R` 输入 `shell:startup`），开机即享丝滑汉化。
