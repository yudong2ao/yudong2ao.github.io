> **精准直击痛点**：Windows 11 色彩管理中加载与显示的永远是 ICC 内部元数据（desc 标签），文件重命名完全无效。用轻量二进制流重写，一次性彻底解决。

## 前言

作为摄影爱好者或多显示器工作者，使用红蜘蛛（Spyder）或爱色丽（i1Display）进行屏幕校色是家常便饭。通常我们会为不同的亮度和使用场景（如“白天 6500K 120nit”、“夜间 6500K 80nit”）生成多个校色文件（`.icc` / `.icm`）。

但如果你在 Windows 11 中尝试理顺这些校色文件，就会遭遇一个非常令人困扰的顽疾：

> **明明在文件管理器中把文件改名成了 `Dell-Day-6500K.icc`，打开系统的“色彩管理 (colorcpl)”后，列表中依然顽固地显示着生成时的旧名字（甚至是一串毫无规律的默认序列号或机型代码）！**

这是因为 Windows 系统的色彩引擎在解析色彩配置文件时，**读取的是文件内部二进制结构中的 `desc` 文本元数据标签**，而非 NTFS 文件系统上的文件名。如果文件内部的名称没有变，改多少次文件名都是徒劳。

手动用十六进制编辑器去改不仅费时费力，稍有不慎改坏了字节长度还会导致文件校验损坏。为此，我用 Node.js 写了这个专门用于重构 ICC 内部名称的极简二进制工具 —— **Icc_Desc_Changer**。

---

## 原理解析：ICC 文件的二进制重构

ICC（International Color Consortium）规范定义了严格的二进制文件结构。在 ICC 文件的头部与 Tag 表中：

1. **Tag Table**：记录了所有数据块的四字节标识符（如 `desc`）以及它们在文件中的偏移量（Offset）与长度（Size）；
2. **TextDescriptionType**：保存了配置文件的展示名称字符串。

修改内部描述并非单纯的“字符串替换”。如果新名字的字符长度与旧名字不一致，**必须动态重新计算 Tag 大小、更新整个 Tag 表的全局偏移量，并保证头部字节对齐**。

本项目通过 Node.js 的 `Buffer` 流精准解析 Tag 映射表，在内存中安全重构整个二进制结构，并在写入前自动备份，确保生成的 ICC 文件 100% 符合规范。

## 快速使用

工具极简无额外依赖，只需机器上具备基础的 Node.js 环境：

### 1. 基础命令语法

打开终端，执行以下命令格式：

```bash
node modify_icc_name.js <目标ICC文件路径> <新的内部显示名称>
```

### 2. 实际操作演示

假设你的当前目录下有一个校色文件 `CSO076D-6500-light.icc`，你想让它在系统设置中直观显示为 `小新Pro13-高亮模式`：

```bash
node modify_icc_name.js ./CSO076D-6500-light.icc 小新Pro13-高亮模式
```

### 3. 双重安全机制

执行后，终端会清晰打印重构过程：

- **安全备份**：脚本会自动在同目录下生成一份 `.bak.icc` 文件（例如 `CSO076D-6500-light.bak.icc`），即便误操作也可瞬间还原；
- **校验输出**：完成二进制校验并覆盖目标文件，确保 Windows 能够无警告加载。

## 如何在 Windows 11 中加载并生效

修改完成后，只需简单几步即可将其应用到屏幕：

1. 按下快捷键 <kbd>Win</kbd> + <kbd>R</kbd>，输入 `colorcpl` 并回车，打开系统**色彩管理**；
2. 在 **设备 (Devices)** 下拉菜单中选中你的显示器；
3. 勾选 **“使用我对此设备的设置”**；
4. 点击底部的 **添加 (Add...)** 按钮，点击浏览，选中修改好的 ICC 文件；
5. 此时你会惊喜地发现，列表中清晰显示着你刚刚指定的中文自定义名称！
6. 选中它并点击 **“设置为默认配置文件”**，屏幕瞬间切换至精准色彩。
